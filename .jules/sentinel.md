## 2024-05-24 - Cross-Site Scripting (XSS) in Inline Event Handlers

**Vulnerability:** The application was vulnerable to Cross-Site Scripting (XSS) due to insufficient escaping of data interpolated into inline JavaScript event handlers (e.g. `onclick`). The code used `escapeHtml` when embedding variables like filenames and document paths into single-quoted JS string literals within HTML attributes, which is insufficient because a user-controlled string containing a backslash or a single quote could break out of the JS string execution context.
**Learning:** Using HTML encoding (e.g., `escapeHtml`) alone is not sufficient when data is placed inside a JavaScript execution context, such as an inline event handler (`onclick="doSomething('${value}')"`). The browser decodes the HTML entities before executing the JavaScript, allowing an attacker to inject arbitrary JS if the string is not also properly escaped for JavaScript (e.g., escaping single quotes).
**Prevention:** Always use a dedicated `escapeJs` function (which escapes backslashes, quotes, and newlines) *before* `escapeHtml` when embedding data into inline event handlers or any JavaScript context. Even better, avoid inline event handlers altogether and use event delegation or `addEventListener` with `data-*` attributes.
